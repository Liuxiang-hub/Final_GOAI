# L20真实服务端 RTC 无硬件冒烟测试

测试链路：Windows客户端 → SSH本地端口转发 → `127.0.0.1:8006` → L20 LingBot-VLA服务。

输入：三路 `640×480×3` 合成静止RGB图、14维零状态和任务指令。全程未打开CAN、未连接或驱动机械臂。

结果：

```text
WebSocket连接：通过
reset("goai_piper_x")：通过
初始推理延迟：418.96 ms
物理动作：action (50,14)，全部为有限值
RTC内部动作：_normalized_actions (50,55)，全部为有限值
RTC后台请求：旧块第15步发起
RTC返回：旧块第39步
实测延迟：24个25 Hz控制步，约960 ms
对齐切换：新块从第24步接入
旧块剩余安全余量：11步，约440 ms
硬件输出：关闭
最终状态：E2E_RTC_SMOKE_OK
```

重要结论：

- `(50,14)` 是反归一化后的物理动作，未来只能由安全适配层处理后交给双PIPER-X。
- `(50,55)` 是模型内部填充动作空间，只用于RTC Flow-Matching约束，不能发送给机械臂。
- RTC请求延迟可能显著高于单次初始推理，现场必须测P95/P99；不能用一次延迟代表稳定性能。
- 50步、25 Hz、第15步触发时总剩余窗口为1.4秒；本次RTC请求约0.96秒，未耗尽但余量有限。
